# UE5 开发工作流（Tirefly 规范）

## 验证哲学（默认纪律）

- UE5 项目开发默认禁止 TDD：不使用 `test-driven-development` 技能、红绿重构循环、测试先行实现或 TDD 式规划；仅当用户明确请求该特定任务的测试时才添加。
- 不要仅为满足通用 agent 工作流或 Superpowers 技能而添加自动化测试。
- 规划 UE5 工作、OpenSpec 任务或验证流程时，默认不设计自动化测试任务/流程步骤；用户明确提到自动化测试时才添加。
- 复杂实时玩法：优先直接实现 + 编译/构建验证。
- 编辑器自动化不可用时：明确标注人工验证点，不强行测试先行循环。
- 自动化测试仅在用户明确要求、或既有项目已要求对进行中变更做特定测试更新时添加。

## 与其他 UE5 技能的分工

- C++ 编译（引擎检测/UBT 路径/项目刷新/编译/失败排查）：`ue5-cpp-compile`。
- C++ 风格（创建/修改/审查/格式化前）：`ue5-cpp-style`。
- UnrealSharp（C# 预检流程/诊断链路）：`unrealsharp-agent-skill`。

## 适用时机

- 任何 UE5 开发任务开始时加载本技能，按上述纪律推进；本技能只承载执行哲学，编译/风格/UnrealSharp 细节走分工技能。
